# FlowHMR Windows v0.3.5

新增纯 CPU 推理和更多 GPU 环境，修复自定义区间仍检测整段素材的问题，并降低 AMD 核显运行 SAM 和运动相机时的内存压力。

- **纯 CPU 推理（实验）。** Intel 和 AMD 的 x64 处理器可选 **运行环境 → CPU**。固定机位、运动相机和 FBX 导出已在 Ryzen 9 9950X 上跑通。没有原生 BF16 时，SAM 会使用 FP32，耗时和内存占用会增加。
- **运行环境按设备推荐。** RTX 50 系列推荐 CUDA 12.8；RTX 20 / 30 / 40 系列推荐 CUDA 12.1；GTX 10 系列可试用 CUDA 12.1。AMD RX 9000 / 7000 系列按显卡匹配 ROCm；为部分 Radeon 核显和 RX 5000 增加实验入口。Intel Arc A / B 和部分 Core Ultra Arc 核显可试用 Intel XPU，由 GPU 执行 SAM 图像编码，其余推理交给 CPU。纯 CPU 与 Intel XPU 暂不支持 HaMeR。
- **减少 SAM 的显存开销。** 跳过动作生成不使用的输出，分阶段加载时先在系统内存初始化 SAM 的人体与手部模型。条件匹配的 AMD 核显可选 **CPU + GPU（省显存）**，由 CPU 编码图像，由 GPU 解码人体和手部姿态。默认仍使用 GPU。
- **核显优先使用固定机位。** 镜头明显转动时可以选运动相机，AMD 核显环境会将相机估计交给 CPU。自动模式最多采样 16 帧，系统内存紧张时会尝试降低分辨率或采样密度。
- **人物检测按选定区间运行。** YOLOX 只扫描设置的起止帧。改区间后会重新检测；预览、原声和多人对齐仍使用原素材帧号。
- **修复系统代理下的角色选择。** PMX、VRM 和 FBX 文件选择后的本机请求会绕过系统代理，继续使用原有会话校验（[Issue #7](https://github.com/xiaoerofficial021-collab/FlowHMR-Windows/issues/7)）。

### 验证范围

| 项目 | 核验结果 |
| --- | --- |
| 纯 CPU 与 AMD 核显 | Ryzen 9 9950X 用纯 CPU 生成同一段四帧动作：固定机位约 28 秒，运动相机约 37 秒。该处理器的内置 Radeon 也完成固定机位生成和 FBX 回读。 |
| SAM 速度与动作 | 同一段四帧素材，AMD 核显的 SAM 用时从 83.61 秒降至 73.76 秒，最大关节位置差小于 0.001 毫米。混合模式的 PyTorch GPU 预留峰值从 4.69 GiB 降至 2.08 GiB，SAM 用时为 76.71 秒。与优化后的 GPU 模式相比，最大关节位置差 1.73 毫米、最大旋转差 0.31°，16 个脚部接触判定一致。 |
| 区间检测与运动相机 | 在 478 帧素材上选第 61–64 帧，人物检测运行四帧，FBX 在 Blender 4.5.3 正常读回。另在模拟核显识别的条件下调用真实 CPU 相机进程，完成 24 帧估计，其中 13 帧参与采样。 |
| 其他硬件 | 已核对新增环境的安装包。RTX 30 / 40 / 50 系列已验证，GTX 10、RTX 20、Radeon 780M / RX 5000 和 Intel XPU 仍在实验中。短片结果不能外推到长视频。 |

已安装的便携版可点击语言菜单旁的 **检查更新**，查看说明并下载，校验完成后重启安装；也可选择已下载的官方 ZIP 手动更新。网络不可用时仍可继续使用当前版本。更新会保留模型、角色库、运行环境、设置和任务历史。
